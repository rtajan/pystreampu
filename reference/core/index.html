    Core classes¶

    These classes are implemented in C++ and exposed with pybind11. Their methods are those of the corresponding StreamPU classes, plus a few Python methods added by streampu (calling a task, operators on sockets…).

    Socket¶

    Socket ¶

    Bases: Interface_reset

    Data exchanged between tasks.

    A socket belongs to a task and has a name, a data type (dtype), a number of elements and a direction (input, output or forward). Its data is a 2D array with one row per frame, accessible without copy through numpy.

    Python operators (+, <, &, x[::2]...) can be used on sockets: each one creates a module, binds it to its operands and executes it.

    Task¶

    Task ¶

    A processing step of a module: the code executed by a node of the data-flow graph.

    A task reads its input sockets, writes its output sockets and modifies its forward sockets. Its sockets are reached by name: task["name"] or task.name.

    Calling a task, task(*sockets), binds the given sockets to its input and forward sockets (in the order of task.sockets), executes it once and returns its output sockets (without status).

    Module¶

    Module ¶

    Bases: Interface_clone, Interface_get_set_n_frames

    Base class of the StreamPU modules: an object that holds tasks.

    The tasks of a module are reached by name, module["task"] or module.task, and their sockets with module["task::socket"]. A module processes n_frames frames per execution of its tasks. spu.help(module) prints its tasks and their sockets.

    clonable property ¶

    clonable: bool

    True if the module can be duplicated on several threads.

    name property writable ¶

    name: str

    Name of the module (can be changed, e.g. to tell modules apart in the statistics).

    stateful property ¶

    stateful: bool

    True if the module keeps a state between executions.

    stateless property ¶

    stateless: bool

    True if the module does not keep any state (it can then be cloned automatically).

    tasks property ¶

    tasks: list[Task]

    Tasks of the module.

    help¶

    Signal_handler ¶

    Handler of the SIGINT (Ctrl+C) and SIGSEGV signals.

    After Signal_handler.init(), a first Ctrl+C sets a flag that stops the running sequences cleanly; a second one kills the program.
